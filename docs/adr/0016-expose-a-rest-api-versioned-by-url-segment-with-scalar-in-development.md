# ADR-0016: Expose a REST API versioned by URL segment, documented with Swashbuckle, with Scalar in Development only

- Status: Accepted
- Date: 2026-11-17
- Deciders: Gihed Annabi

## Context

The phone, the admin app and the smoke tests call the parking data service. Pivot.Framework offers REST through
`Pivot.Framework.Containers.API` (`ApiController`, ProblemDetails, `AddPivotApiVersioning()` with URL segment, header
and query readers, and Swashbuckle through `WithSwagger`) and gRPC through `Pivot.Framework.Containers.Grpc`. The
scaffolding rules allow the reference page outside Development only with an ADR. Phones update late, so old app
versions must keep working.

Options considered:

1. REST with URL-segment versioning, Swashbuckle's OpenAPI document and Scalar in Development.
1. gRPC.
1. REST with `Microsoft.AspNetCore.OpenApi` and a generated client (Kiota or NSwag).

## Decision

We expose REST over HTTPS with JSON (option 1).

- Controllers derive from Pivot's `ApiController` and return `HandleResult` or `HandleFailure`; errors are
  ProblemDetails, with the problem type `parking-data-stale` for stale data.
- `AddPivotApiVersioning()`; the documented form is the URL segment `/api/v1/...`.
- The OpenAPI document is generated by Swashbuckle (Pivot's `WithSwagger`) and is the contract. A snapshot
  `openapi.v1.json` is committed and compared in a test; every operation has a summary, its responses, its security
  requirement and examples (`docs-api-contracts`).
- Scalar (`MapScalarApiReference`) is mapped in Development only (decided by default, the owner may change it). The
  OpenAPI document and the Scalar page are not mapped in Production; exposing either needs a new ADR.
- Transport records live in `ParkingTracker.Contracts` and mirror the domain value objects field by field.
- Data responses carry `ETag` and `Cache-Control: private, max-age=300`; Brotli and gzip compression are on.
- A breaking change creates `v2` beside `v1`; `v1` stays until the last app version using it is below 5 % of active
  installs. `GET /api/v1/client-config` carries the minimum supported app version.

## Consequences

### Positive

- One OpenAPI generator, the framework's controller base and ProblemDetails mapping.
- Works through Caddy and from the admin app without HTTP/2 end to end.
- The version is visible in URLs, logs and the app's fallback logic.

### Negative

- JSON polygons are larger than a binary encoding; compression and the later bundle endpoint mitigate it.
- No browsable reference in Production; diagnosing a production contract question needs the committed snapshot.
- Keeping `v1` alive while old phones exist costs maintenance.

## Alternatives considered

- **gRPC** - rejected. It needs HTTP/2 end to end through the proxy and gRPC-Web for the browser-based admin app, and
  generated message types would not be the domain-shaped records the parity relies on.
- **`Microsoft.AspNetCore.OpenApi` and a generated client** - rejected. It adds a second OpenAPI generator next to the
  Swashbuckle one that `WithSwagger` already registers.
- **Scalar public in Production** - rejected by default. It advertises the full surface, including the session
  endpoints, for no user benefit.
